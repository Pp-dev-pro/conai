Model, data & architecture

How the app is built, what the machine learning model is, and what the 1030-sample dataset tells us.

01 How the app is built

ConcreteAI is a native Android app written in Java, so it is fast and works without internet. It is the first concrete strength prediction project built natively in Java for Android; the earlier published model was Python desktop software.

  • Reading inputs: collects the eight values from the cards.
  • Validation: empty or impossible values are caught first.
  • Feature array: values arranged in the exact training order.
  • Prediction: the tree-based model calculates strength.
  • Display: result ring plus analytics.

Because the model sits inside the app, no data leaves the phone and no server is needed.

02 The machine learning model

The engine is a Deep Forest combining Random Forest and ExtraTrees regressors. Deep Forest (Zhou and Feng, 2017) stacks layers of tree ensembles instead of neural layers, which suits small tabular datasets. The design follows Zhang et al., Scientific Reports 14, 18918 (2024), which compared twelve regression models with grid search and fivefold cross-validation.


Data split (about 8:2): Training 822 samples, Testing 208 samples. Test samples are never seen in training.

Deep Forest scored the best R² of 0.91, all tree models exceeded 0.90, and LASSO was lowest at 0.61. On the app's analytics screen: MAE 3.397, RMSE 4.958, R² 0.907.

03 The dataset

Trained on the Concrete Compressive Strength dataset from the UCI Machine Learning Repository (ID 165), created by Prof. I-Cheng Yeh: 1030 laboratory samples, eight inputs, one output, no missing values.

04 What the data tells us

Cement and superplasticizer relate positively to strength; water has the strongest negative relation (−0.29).

Age matters most. Age alone gave the best single-factor R² of 0.39 and a five-factor subset reached 0.83. Strength climbs steeply in the first 28 days, then flattens.

05 Catalyst cloud website & API

The site sends the eight values over HTTPS to a Java function on Catalyst. The function adds the secret key and OAuth token and calls the QuickML endpoint, so no secret ever reaches the browser.
